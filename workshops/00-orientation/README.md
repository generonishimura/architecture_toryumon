## アジェンダ

### 1. イントロダクション（15分）

- ワークショップ「アーキテクチャ登竜門」の趣旨説明
- 「アーキテクチャ」とは何か：ソフトウェアにおける設計判断の集合
- 本ワークショップで扱う範囲と扱わない範囲

> **講師メモ**: 「アーキテクチャ」という言葉は抽象的に聞こえがちです。まずは「ソフトウェアの構造に関する、後から変えにくい判断のこと」という定義を共有しましょう。Ralph Johnson の「アーキテクチャとは重要なもののこと。それが何であれ」という言葉を引用すると、後から変えにくい判断ほど慎重に決める必要があることを、参加者が理解しやすくなります。
>
> 扱う範囲（アプリケーションアーキテクチャ、データ設計、分散システム）と扱わない範囲（インフラ構築の実務、フロントエンドフレームワーク固有の設計、セキュリティの詳細）を最初に示します。そうすると、参加者はこの講座で何を学べるかを把握したうえで受講できます。

### 3. 全体ロードマップの紹介（15分）

#### 3つのフェーズの意図

本ワークショップは3つのフェーズで構成されています。

```
フェーズ1: 基礎（第1〜3回）
  オブジェクト指向 → RDB → データモデリング
  「1つのアプリケーション内のコードとデータの設計」を固める

フェーズ2: 設計パターン（第4〜6回）
  デザインパターン → DDD → クリーンアーキテクチャ
  「設計の引き出しを増やし、アプリケーション全体の構造を設計する力」を養う

フェーズ3: 分散システム（第7〜9回）
  マイクロサービス → オーケストレーション → イベント駆動
  「複数のアプリケーション（サービス）にまたがるシステム全体の設計」を学ぶ
```

フェーズが進むにつれて、扱う範囲が広くなる構成です。最初は関数やクラスの設計を扱い、最後はシステム全体のアーキテクチャを判断できるようになることを目指します。後の回は前の回の内容を前提にしているので、回を飛ばさずに順番に受講してください。

### 6. ウォームアップ：設計について考える（15分）

以下の問いについて、グループで議論する。

- 「良いコード」と「良い設計」の違いは何か？
- 設計で一番困った経験は？
- なぜアーキテクチャを学ぶ必要があるのか？

> **ファシリテーションのコツ**: この議論に正解はありません。目的は、参加者が設計についての考えを自分の言葉で説明してみることです。次のような観点が参加者から出るように問いかけます。
>
> - **良いコード** = 読みやすい、バグが少ない、テストしやすい（局所的な品質）
> - **良い設計** = 変更しやすい、拡張しやすい、チームで開発しやすい（構造的な品質）
> - 「コードは正しく動くが、設計が悪いので新機能を追加するたびに苦労した」という参加者自身の経験を聞きましょう
>
> 出てきた意見はホワイトボードに書いて記録しておきます。最終回（第10回）でこの記録を見返すと、参加者は自分の考えがどう変わったかを確認できます。

**TypeScriptの実行環境の準備手順**

TypeScriptはグローバルにインストールしない。プロジェクトごとに `typescript` と `tsx` と `@types/node`（Node.jsの型定義）を入れる。こうすると、プロジェクトごとに使うTypeScriptのバージョンを固定できる。

```bash
mkdir toryumon-workspace && cd toryumon-workspace
npm init -y
npm pkg set type=module   # ES module として扱う（第2回の Prisma 7 の前提とそろえる）
npm install -D typescript tsx @types/node
echo "const message: string = 'hello'; console.log(message);" > hello.ts
npx tsx hello.ts   # hello と表示されれば準備完了
```

- WindowsのPowerShellでは、`echo ... > hello.ts` で作ったファイルがUTF-16で保存され、`npx tsx` で実行できないことがある。Windowsでは、`hello.ts` をエディタで作る（または `Set-Content -Encoding utf8` を使う）
- 型チェックをするときは、作業用ディレクトリに次の `tsconfig.json` を置き、`npx tsc --noEmit` を実行する。`npx tsc --init` が出力する設定は `"module": "nodenext"` などになっている。この設定では拡張子のない相対import（`'./generated/prisma/client'` など）がエラーになるので、この教材では使わない

```json
{
  "compilerOptions": {
    "target": "es2022",
    "module": "esnext",
    "moduleResolution": "bundler",
    "types": ["node"],
    "strict": true,
    "skipLibCheck": true,
    "noEmit": true
  },
  "include": ["src", "*.ts"]
}
```

- Expressを使う回では、`@types/express` も必要になる（`npm install -D @types/express`）
- `node hello.ts` では、教材のコード（`constructor(private readonly ...)` のようなパラメータプロパティなど）を実行できない。教材のコードは `npx tsx` で実行する
