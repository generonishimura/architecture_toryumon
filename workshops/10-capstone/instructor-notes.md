# 第10回 総合演習・振り返り：講師補助資料

## この回のキーメッセージ

> 「正解は1つではない。トレードオフを理解し、根拠を持って判断することが大切」

最終回は、講義よりも演習とファシリテーションが中心になる。講師は答えを教えず、質問をして参加者に考えを話してもらう役に回る。

## 講師の事前準備チェックリスト

- [ ] 第1〜9回の核心メッセージを一覧で復習し、各テーマの要点を1分以内で説明できるようにする
- [ ] 演習題材の詳細要件を作成・確定する（README例の「オンライン学習プラットフォーム」またはカスタム題材）
- [ ] グループ分けを事前に決める（スキルバランスを考慮。各グループに経験豊富な人を分散させる）
- [ ] ホワイトボードまたはオンラインホワイトボード（Miro, FigJam等）を準備・動作確認する
- [ ] KPT振り返りシート（テンプレート）を準備する
- [ ] （任意）修了証を準備する
- [ ] 各グループが参照できる「テーマ別キーワードカード」を印刷またはデジタル配布する

## 時間配分ガイド（合計150分。他の回とは構成が異なる）

| パート | 配分 | 注意点 |
|--------|------|--------|
| **全体振り返り** | **25分** | 講師が話しすぎない。参加者に各テーマを語ってもらう |
| グループ分け + 要件読み合わせ | 15分 | 要件の不明点をここで解消する |
| **設計ワーク** | **30分** | 巡回して進み具合を確認。議論が止まっているグループにヒントを出す |
| **各グループの発表** | **30分** | 1グループ10分（発表7分 + 質疑3分）|
| 講師フィードバック + 全体ディスカッション | 15分 | |
| 休憩 | 10分 | |
| KPT振り返り | 15分 | |
| 次のステップ + クロージング | 10分 | |

- 4グループ以上の場合は、発表を1グループ6分（発表4分＋質疑2分）にする。または、全体振り返りを15分に短縮し、空いた10分を発表時間に回す

## 全体振り返りの進め方

9テーマを講師が全部説明すると長くなりすぎる。次の方式を推奨する。

1. テーマ一覧をスライドに表示する
2. 各テーマについて参加者1人を指名し、「このテーマの核心を一言で」と答えてもらう
3. 講師は補足・修正のみ行う
4. テーマ間のつながり（依存関係図）を最後に示す

目標：25分で9テーマを短く振り返り、演習の準備を整える

## 演習のファシリテーションガイド

### グループ分けのポイント
- 1グループ3〜4人
- 各グループにフェーズ3（分散システム）に詳しい人を1人は入れる
- 発言が少ない参加者が1つのグループに集まらないようにする

### 設計ワーク中の巡回

**最初の5分**は、各グループが何から手を付けるか迷うことが多い。次の声かけが有効である。
- 「まずドメインの主要なエンティティを洗い出してみてください」
- 「境界づけられたコンテキストは何個ありそうですか？」
- 「モノリスで始める？マイクロサービスにする？その判断理由は？」

**15分経過時点**で、次の点を確認する。
- 図を描き始めているか？
- 全員が議論に参加しているか？
- 1つのトピックで止まっていないか？

**介入すべきタイミング**は次の3つ。
- 議論が完全に止まっているとき → 具体的な質問をする
- 1人だけが話しているとき → 「他の方はどう思いますか？」
- 細部に入りすぎているとき → 「まず全体像を決めてから細部に入りましょう」

### 発表時のポイント

発表者には次のことを伝える。
- **「何を選んだか」より「なぜ選んだか」**を説明してください
- トレードオフ（何を得て、何を犠牲にしたか）を明示してください
- 第1〜9回で学んだ概念を使って説明してください

質疑は建設的に進める。「それは間違い」と言わずに、「別のアプローチとして○○もあるが、どう比較しましたか？」と聞く。

### 講師フィードバックのポイント
- 各グループの良かった点を必ず1つ以上挙げる
- 「正解」は示さない。「こういう観点も考えられる」という形で、別の視点を追加で示す
- グループ間の設計の違いを比較し、「同じ要件でも設計が異なる。それぞれに合理性がある」とまとめる

## 演習題材の準備（README例の補足）

README記載の「オンライン学習プラットフォーム」を使う場合、次の追加情報を用意しておくと、議論の材料になる。

- 想定ユーザー数: 月間アクティブ10万人
- 同時視聴ピーク: 1万人
- コース数: 1,000コース
- 地域: 日本国内限定
- チーム構成: バックエンド5人、フロントエンド3人、インフラ2人

別の題材候補を次に挙げる。
- フードデリバリーサービス（UberEats風）
- チケット予約システム（映画館）
- リアルタイムチャットアプリ（Slack風）

## KPT振り返りの進め方

1. 各自で付箋（物理またはデジタル）にKeep/Problem/Tryを書く（5分）
2. グループ内で共有（5分）
3. 全体で主要なものを発表（5分）

良いTryを出してもらうための問いの例を次に挙げる。
- 「明日から実務で使えそうな概念は？」
- 「チームに共有したいテーマは？」
- 「もっと深く学びたいテーマは？」

## 想定される質問と回答例

| 質問 | 回答の方向性 |
|------|-------------|
| 「設計の答え合わせをしてほしい」 | 「答えは1つではない。重要なのは判断の根拠。今日の経験から、自チームでも根拠を持って設計議論できるようになってほしい」 |
| 「全テーマ網羅した設計は時間的に無理」 | 「全部やろうとしなくてよい。必須の2観点（境界づけられたコンテキストの識別、サービス分割の判断）に、選択の観点を1〜2個足して深く議論するほうが学びが大きい」 |
| 「この後どうやって実務に活かせばいい？」 | 「ADR（Architecture Decision Record）で設計判断を記録する習慣から始めるのがおすすめ。小さく始めて、チームに広げていく」 |

## クロージングで伝えたいこと

- 「11回のワークショップで学んだのは、基礎の知識です。大切なのは、ここから実務で使うことです」
- 「設計に正解はありませんが、『なぜこの設計にしたか』を言葉で説明できるようになったことが、このワークショップの最大の成果です」
- 「同じテーマを学んだ仲間がいることにも価値があります。皆さんは、設計について同じ用語で議論できるようになりました」
