# 企画概要・コンセプト

## 企画名

**アーキテクチャ登竜門**（Architecture Toryumon）

## コンセプト

「登竜門」とは、困難だが突破すれば大きく成長できる関門を意味します。本ワークショップは、ソフトウェアアーキテクチャのテーマを1回に1つずつ扱い、基礎から応用まで順に学ぶ構成です。

各回では、扱うテーマが他の回のテーマとどうつながるかも説明します。目標は、実務で設計判断ができるエンジニアを育てることです。

## 背景・なぜこの企画が必要か

実務経験2〜5年目のエンジニアには、コードを書く力はあっても、次のような課題がよく見られます。

- **設計判断の根拠が持てない**：なぜこの構造にするのか説明できない
- **知識が断片的**：DDD、クリーンアーキテクチャ等の用語は知っているが体系的に理解していない
- **全体像を把握できていない**：オブジェクト指向からマイクロサービスまでがどうつながるか分からない
- **実務への適用が難しい**：書籍で学んでも、現場のコードにどう適用するか判断できない

本ワークショップは、これらの課題を解決するために、基礎のテーマから応用のテーマへ順に進む構成にしています。

## 目的・ゴール

### 全体目的

ソフトウェアアーキテクチャの基礎〜応用を体系的に学び、設計判断のときに検討できる選択肢を増やすことが目的です。

### 到達目標

本ワークショップの到達目標は次のとおりです。完了した参加者が、これらをできるようになることを目指します。

1. **オブジェクト指向の原則に基づいた設計ができる**：SOLID原則を意識したクラス設計
2. **データベース設計の基本を理解している**：正規化、インデックス戦略
3. **ドメインモデルを設計できる**：ユビキタス言語を用いた概念モデルの構築
4. **適切なデザインパターンを選択できる**：問題に対してパターンの適用判断ができる
5. **レイヤー構造を設計できる**：クリーンアーキテクチャの原則に沿った構成
6. **分散システムの基本的なトレードオフを理解している**：マイクロサービス、イベント駆動の利点と課題

## 対象者

### 想定する参加者像

- 実務経験2〜5年目のソフトウェアエンジニア
- 日常的にTypeScript / JavaScriptでコードを書いている
- チーム開発の経験がある（Git、コードレビュー等）
- 「もっと良い設計にしたい」と感じているが、具体的にどうすれば良いか分からない

### 前提知識

- TypeScriptの基本文法（型、インターフェース、クラス、非同期処理）
- Node.jsの基本的な使い方
- Gitの基本操作
- SQLの基本（SELECT, INSERT, UPDATE, DELETE）

### 対象外

- プログラミング未経験者
- すでにアーキテクトとして設計経験が豊富な方（レビュアー・メンターとしての参加は歓迎）

## 形式

| 項目 | 内容 |
|------|------|
| 形式 | 座学中心（講義 + コード例 + 議論） |
| 1回あたりの時間 | 2.5時間（150分）。第0回（オリエンテーション）のみ90分 |
| 頻度 | 週1回 |
| 全回数 | 全11回（オリエンテーション + 9テーマ + 総合演習） |
| 期間 | 約3ヶ月 |
| 技術スタック | TypeScript / Node.js |
| 課題 | 各回終了後に復習課題を出題 |

### 各回の構成（標準）

```
[5分]   前回の振り返り・課題の共有
[100分] 講義（概念説明 + TypeScriptコード例）
[10分]  休憩
[20分]  ディスカッション
[10分]  Q&A
[5分]   次回予告・課題説明
（合計150分）
```

第0回（オリエンテーション）は90分で、構成が異なります。第10回（総合演習）は、グループ発表などのために独自の配分を使います（合計は150分）。各回の詳しい配分は、各回の講師ノート（`workshops/XX-xxx/instructor-notes.md`）の「時間配分ガイド」に書いてあります。

## 運営方針

### 大切にすること

- **「なぜ」を大切にする**：技術の使い方だけでなく、なぜその設計が必要かを伝える
- **段階的な構成**：前回までに学んだ内容を前提にして、新しい概念を説明する
- **具体的なコード例**：概念の説明に、TypeScriptの具体的なコード例を添える
- **議論を重視**：各回に、参加者同士で話し合う時間を設ける
- **完璧を目指さない**：すべてを網羅することより、中心となる概念の理解を優先する

### 講師に求めること

- 各テーマについて実務経験に基づいた具体例を交えて説明できること
- 参加者の質問に対して、教科書的な回答だけでなく実務的な視点で答えられること
- 「正解」を押し付けず、トレードオフを示して参加者に考えさせること

## 期待される成果

- 参加者同士が、アーキテクチャについて同じ用語で話せるようになる
- 参加者が、設計レビューやアーキテクチャ選定の場で根拠を示して議論できるようになる
- チーム全体の設計力を上げることにつながる
